Phase 2. 직면한 병목
실무 적용 시 직면한 4가지 핵심 장애요인 (기술 원인 + 쉬운 예시)
1. 과도한 블랙박스 추상화 (Over-abstraction)
💻 기술적 원인: LangChain 내부 `PromptTemplate`, `LCEL`, `Chain` 등 수십 겹의 래퍼(Wrapper) 클래스로 로직이 감싸여 있어, 챗봇 응답이 느리거나 잘못된 검색 결과가 나왔을 때 내부 콜스택 Traceback 추적 및 속도 병목 진단에 막대한 시간과 타임 손실 발생.
💡 쉬운 일상 비유: 음식을 시켰는데 식당과 배달원 사이에 중간 대리점 5곳을 더 거치는 구조입니다. 배달이 늦거나 음식이 잘못 왔을 때 어느 대리점에서 문제가 생겼는지 내부를 열어볼 수 없어 원인 파악이 불가능한 상황과 같습니다.
2. 잦은 라이브러리 구조 변경 (Maintenance Risk)
💻 기술적 원인: LangChain 생태계의 패키지 분리(`langchain-community`, `langchain-core` 등)와 빈번한 메소드 Deprecation으로 인해 라이브러리 패치 시 기존 코드가 작동안 하는 Breaking Change가 빈번하여 운영(Production) 환경의 지지 안정성을 위험하게 만듦.
💡 쉬운 일상 비유: 새로 산 자동차의 부품 규격과 운전대 조작법이 매달 바뀌어, 차량을 수시로 카센터에 입고시켜 재조립해야 하는 위험과 같습니다.
3. 불필요한 실행 지연시간 (15%~30% Latency Overhead)
💻 기술적 원인: 단순한 백엔드 API 호출임에도 수십 단계의 내장 함수 객체 및 체인 래퍼 콜스택을 통과하며 실행 지연시간(Latency)과 메모리 풋프린트 오버헤드가 15%~30% 추가 소요됨 (arXiv:2403.05838 벤치마크).
💡 쉬운 일상 비유: 간단한 편지를 보낼 때 서류 봉투를 10중으로 포장하고 개봉하느라 서류 전달 시간이 지연되는 현상입니다.
4. 연구원 맞춤형 미세 수선(Fine-Grained Tuning)의 한계
💻 기술적 원인: 본 사업의 핵심 과업인 **3072차원 시맨틱 의도 프로파일링**, **코사인 유사도 기반 동적 신뢰도 점수(80%~98%) 환산**, **원문 출처 각주(`[1]`, `[2]`) 정밀 맵핑** 및 **429 Rate Limit 예외 가드레일**을 정밀 제어하기에 프레임워크 템플릿 규격이 오히려 장애물이 됨.
💡 쉬운 일상 비유: 기성복 정장을 샀는데 치수가 안 맞아 연구원 특성에 맞게 바지 기장을 수선하려 해도 수선 자체가 금지되어 있는 구조입니다.

📌 2. 코사인 유사도 (Cosine Similarity) 원리 및 시스템 적용

두 3072차원 벡터 사이의 각도를 측정하여 단순 단어 일치가 아닌 '문맥적 의미 유사도'를 수치화합니다. (-1.0 ~ 1.0)

Cosine Similarity (A, B) = (A · B) / (||A|| × ||B||)

본 RAG 시스템에서의 3대 코사인 유사도 핵심 역할

1
키워드 불일치 완전 극복 (시맨틱 매칭)

"이민" vs "이주민", "추산치" vs "규모" 등 표면 단어가 달라도 3072차원 문맥 거리로 정확히 검색합니다.

2
Semantic Intent Profiling (질문 의도 자동 분류)

하드코딩 키워드 없이 사전 계산된 3대 의도(통계 지표 / 정책 효과 / 연구보고서) 벡터와 코사인 유사도를 연산하여 의도를 분류합니다.

3
동적 신뢰도(Confidence Score) 산출 (80% ~ 98%)

유사도 최댓값을 바탕으로 객관적 신뢰 점수를 실시간 계산하여 환각 차단 가드레일 기준으로 작동합니다.

📌 3. 지능형 RAG 서비스 비즈니스 워크플로우 (12 Step)
1
사용자 질문 입력

Next.js 프론트엔드에서 자연어 질문 수신 ("관광산업 정책 파급 효과 알려줘")

2
Gemini 임베딩 3072차원 벡터화

입력된 질문을 3072차원 고밀도 시맨틱 벡터로 변환

3
의도 분석 (Intent Profiling)

3대 대표 의도 벡터와 코사인 유사도를 즉시 연산하여 질문 의도 자동 분류

4
ChromaDB 시맨틱 탐색 (HNSW)

로컬 영속 ChromaDB에서 관련 연구보고서 Top-K 청크 검색

5
동적 신뢰도 계산 및 가드레일 평가

코사인 유사도 기반 신뢰도 점수(예: 92%)를 측정하고 근거 부족 여부 검증

6
팩트 그라운딩 브리핑 작성 & 답변 제공

Gemini 3.6 Flash 모델이 원문 출처 각주([1], [2])를 포함한 브리핑 작성 후 프론트엔드 시각화

7
사용자 피드백 영속 적재

답변 피드백(좋아요/아쉬워요)을 SQLite 로컬 DB에 보존하여 재학습 선순환 구조 구축

📌 4. 보안 및 가드레일 (Security & Safety)
🔑 API Key 완벽 격리
Gemini API Key 등 핵심 자격증명은 백엔드 환경변수(`.env`)에 격리되어 클라이언트 브라우저로 전혀 노출되지 않습니다.
🛡️ No-Ops 온프레미스 DB
외부 클라우드 데이터베이스 전송 없이 연구원 내부 디스크(ChromaDB Local)에 영속 보존하여 데이터 외연 유출 제로화.
⏱️ 429 Rate Limit 예외 처리
Gemini API 429 Quota Exceeded 발생 시 `QuotaExceededException` 가드레일이 작동하여 서비스 멈춤 없는 안전 멘트 출력.
🚫 환각(Hallucination) 차단
코사인 유사도가 설정 임계치 미만일 경우 억지로 답변을 조합하지 않고 "근거 데이터 부족" 안심 멘트를 출력합니다.
